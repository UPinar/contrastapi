Security data and monitoring
for developers and AI agents.

Security data as structured JSON over REST and MCP: CVE, EPSS and KEV, package (SBOM) vulnerabilities, domain and IP intelligence. A Pro key watches CVEs, packages, domains and IP addresses, and you read what changed as events. The free tier needs no API key.

CVE Intelligence

Look up, search and rank CVEs with EPSS and KEV. See CVE, EPSS & KEV API with Monitoring.

GET /cve_lookup/{cve_id} CVE details + EPSS + KEV; ?include_ghsa=true adds the GitHub Security Advisory
POST /cve_lookup_bulk Bulk CVE lookup (up to @@CVELOOKUPBULK_MAX_IDS@@ IDs per request)
GET /cve_products/{cve_id} The products a CVE affects, one page at a time, vulnerable ones first
GET /cve_search Search CVEs (paginated)
GET /cve_leading Top CVEs ranked by EPSS, then CVSS: a quick exploit-probability briefing
GET /kev_lookup/{cve_id} CISA KEV entry (due date, required action, ransomware use, CWE list)
GET /cwe_lookup/{cwe_id} MITRE CWE catalog (description, mitigations, examples, parent CWE)
GET /cve_risk_score/{cve_id} Composite risk score (exploitability + impact + evidence, 0-100) + label
GET /cve_exploit/{cve_id} Public exploit intelligence: GitHub PoCs, Metasploit modules, NVD exploit references, ExploitDB entries
GET /cve_triage CVEs ranked by composite risk score: what to patch first
POST /cve_triage_bulk Rank your own list of CVE IDs by composite risk score (up to @@CVETRIAGEBULK_MAX_IDS@@ IDs)
GET /product_exposure CVE exposure of one product: severity/KEV/PoC counts, worst scores, top CVEs by risk, and its end of life dates
GET /cpe_search Find CPE vendor and product names, ranked by vulnerable CVE count
GET /cvss_calculator Decode a CVSS v3.0/v3.1 vector into its base metrics + recomputed scores

Domain Intelligence

DNS, mail authentication, TLS, headers, registration and certificate data of a domain. See Domain Intelligence & Monitoring API.

GET /dns_lookup/{domain} DNS records (A, AAAA, MX, NS, TXT, CNAME, SOA, CAA), non-public addresses and the services TXT records name
GET /dns_takeover_check/{domain} A dangling CNAME, and whether a known service lets anyone claim its target
GET /email_auth_check/{domain} SPF, DMARC, DKIM, MX and MTA-STS records, with a pass, warn or fail for each check
GET /email_address_check/{email} Whether an email address's domain takes mail, and whether the address is disposable; no mail is sent
GET /ssl_check/{domain} The TLS version, cipher and certificate on port 443: whether the certificate is trusted, whether the SSL Blacklist lists it, and the days until it expires
GET /headers_check/{domain} The security headers of a web site's home page, rated: CSP, HSTS, X-Frame-Options, Set-Cookie and five more, each with its issues and a fix
GET /whois_lookup/{domain} The registrar, dates, status values and name servers of a domain, over RDAP, or over WHOIS for a TLD without RDAP; no registrant or contact data
GET /wayback_lookup/{domain} When the Wayback Machine first and last captured a host's home page, and its latest 10 capture days, each with a link
GET /cert_search/{domain} The unexpired certificates that Certificate Transparency logs hold for a host name, from Cert Spotter, read up to 5 pages: up to 10 whose validity starts last, each with its issuer, validity, revocation and DNS names
GET /subdomain_enum/{domain} The subdomains of a registrable domain, from Certificate Transparency, DNS guesses of 94 common names and the domain's MX, NS and SPF records: up to 50 names, each with its sources, and a wildcard DNS check

Monitoring (watchlist)

Monitoring needs an API key. Add CVEs, products, CVE searches, packages, domains and IP addresses to the watchlist of your key. The server records change events for them. You read the events with watchlist_events. See Security Monitoring API.

POST /watchlist_edit Add, remove, list or clear the CVEs, products, CVE searches, packages, domains and IP addresses your key watches
GET /watchlist_events The CVE, package, end-of-life, domain and IP changes that match your watchlist, oldest first; the server keeps your position

FAQ

Do I need an API key?
For monitoring (the watchlist tools) and for saving your own vendor keys. Every other endpoint works without authentication on the free tier. Just send requests. Pro users send their key in the Authorization: Bearer header or the X-API-Key header.
What happens when I hit the rate limit?
You'll get a 429 response with a Retry-After header: the seconds until your hourly budget resets. The free tier has @@RL_ANON_CREDIT_LIMIT@@ credits per hour; a Pro key has @@RL_KEY_CREDIT_LIMIT@@.
How do I check that the API is up?
Call /health. It reports the database's freshness and the sync state of each data feed, and it costs no credit.

Data Freshness

  • CVE / EPSS / KEV / CWE: synced from NVD, FIRST EPSS, CISA KEV and MITRE CWE into the local database. /health shows when each feed was last synced and whether that sync succeeded.
  • Exploit and detection data: /cve_exploit reads local copies of the PoC-in-GitHub list, the Metasploit module list and the Exploit Database list. A GitHub repository is listed, but it is not counted as proof of a public exploit. /cve_lookup and the has_nuclei_template filter of /cve_search and /cve_leading read a local copy of the Nuclei template list.
  • Product names: next to the CPE names of NVD, the affected products carry the names a CNA gives. The NVD record holds the CNA's names in free text. The CVE List of the CVE Program (cvelistV5) holds the CNA's CPE names.
  • Advisory data: ?include_ghsa=true, /package_check and /package_check_bulk read a local copy of the OSV.dev export.
  • End-of-life dates: the eol member of /product_exposure, /package_check and /package_check_bulk reads a local copy of the endoflife.date data (MIT).
  • Leaked passwords: /password_check asks the Pwned Passwords range API of Have I Been Pwned when it is asked. It sends only the first five characters of the SHA-1 hash.
  • Driver data: /driver_lookup and /driver_lookup_bulk read a local copy of the LOLDrivers catalog.
  • IP data: /ip_lookup reads local copies of the IPtoASN list, the DB-IP Lite country list (IP Geolocation by DB-IP), the published address ranges of cloud and CDN providers, the Tor exit list and a list of hijacked netblocks. /asn_lookup reads the same copy of the IPtoASN list. For a Pro key that saved its own Shodan or AbuseIPDB key, /ip_lookup also asks Shodan and AbuseIPDB when it is asked.
  • Email data: /email_address_check reads a local copy of the disposable-email-domains blocklist (CC0 1.0). It asks its own DNS resolver about the address's domain when it is asked.
  • Defense data: /d3fend_for_attack reads a local copy of the MITRE D3FEND catalog. The copy is refreshed every week from MITRE.
  • TLS checks: /ssl_check connects to the host when it is asked. It keeps a successful answer for one hour when it could read the SSL Blacklist and the list holds rows, and checked_at says when the check ran.
  • Header checks: /headers_check fetches the home page of the host when it is asked. It keeps each successful answer for one hour under the host name and the choice of whole values. The answer holds the address of the page without its query, the site's status, the target of a redirect it did not follow and the security headers the site sent. It holds no Set-Cookie value, only counts: how many cookies the site set, and how many have each issue. Any caller who makes the same request in that hour gets it, and checked_at says when the fetch ran.
  • Domain registrations: /whois_lookup asks the RDAP server of the TLD when it is asked. It finds that server in a copy of IANA's RDAP bootstrap file. A TLD without an RDAP server is asked over WHOIS, when the registry's terms allow it. It keeps each answer that holds a registration for one hour.
  • Web archive captures: /wayback_lookup asks the CDX server of the Internet Archive's Wayback Machine when it is asked. It reads only the list of captures, and it keeps each answer that holds that list for one day.
  • Certificate Transparency: /cert_search asks SSLMate's Cert Spotter when it is asked. Cert Spotter lists only unexpired certificates. The server keeps each answer that holds the certificate list for one day.
  • Subdomains: /subdomain_enum asks its own DNS resolver and Cert Spotter when it is asked. It keeps each answer under the registrable domain: for one day when it holds the names of Cert Spotter, and otherwise for 10 minutes, or for the wait it names when that is longer. An answer whose wildcard verdict is undetermined is kept for 10 minutes.
